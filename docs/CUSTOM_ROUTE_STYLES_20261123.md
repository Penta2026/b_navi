# B_Navi PWA — カスタムルート4スタイル（2026-11-23 試験実装）

## 既存機能との位置関係
既存のビギナー／一般／探索／126cc以上のファストトラベルを維持。
走り方プルダウンに **「カスタムルート（4スタイル）」** を追加し、次の4択を表示する。

- 🌿 景観優先：森林・水辺の推定タグを使って景観寄り。右左折を減らす
- 🎯 効率優先：遠回りや狭い道を抑え、目的地まで効率を重視
- 🛵 裏道優先：地方道路・一般道路を優先し、右左折や細道を許容
- 🏍️ 快走優先：道幅と連続性を優先し、右左折を減らす

従来の「🎛 カスタマイズ」3軸スライダーは**独立のまま残す**。
スライダーON時は一般BRFの3軸調整、カスタムルート選択時は4スタイル専用BRF。
同時適用しない。設定はローカル保存され、同じ条件で再探索する。

**推定値／試験値。実ルートで効果を確認したMAX・閾値ではない。**
各車種はそれぞれの元の「一般BRF」に、125cc元値との差分を加算する。
法的アクセス制限、通行禁止、路面補正、生活道路回避などは原本のまま維持する。
その他一般道路はBRFの `unclassified` に対応し、
`residential`・`living_street`・`service` の元の抑制は保持する。

## 適用制約

- 「信号が少ない」を最重要視する意図で、**OSMに登録済みの信号**に強いコストを置く。計測済み信号数や実交通量ではない。
- 交通の「流れの良さ」は実時間・渋滞情報を持たないため直接測定しない。車線・道路種別と信号の代理評価のみ。
- 景観はOSM由来の `estimated_forest_class`／`estimated_river_class` がある道路でのみ効く。森林と水辺は重複加算しない。
- 危険な通行禁止を回避するため、各車種の一般BRFから法的アクセス制約を緩和しない。既存の50cc／125ccの原付専用経路などの制約はそのまま。
- **カスタムルートは公開BRouterでのルート計算時のみ有効。** 専用Java API接続時は、設定を無視して一般ルートで計算せず、未対応エラーを表示する。
- 公開BRouterのサービス利用上限・availability、OSM通行条件の欠落などは別途注意。

## 検証
Node単体テストで BRF生成と危険なアクセス制限の維持、既存ルートの無変更を検証する。
今後、同一路線・同一路点・同車種でモード比較し、信号・右左折・距離・道幅と景観タグの変化を実測する。
スマホ実機、実際のBRouter計算、走行試験を済ませるまでは本番向け品質と主張しない。
